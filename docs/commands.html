Command guide

Every command, and where it works.

/cade … commands work at the top of a channel. @Cade … commands are messages, so they also work in threads, where most of the work happens. Most of the time you won't need either: Cade offers what you're about to do, privately, and you click.

Start

Requirements, incidents and tasks

/cade requirement

Client channelTop level

Opens a form for the requirement's name, priority and an optional due date, then posts it as a new message whose thread is where it's discussed. The card shows its status, priority and due date, and stays pinned until it's done.

Example: “Deposit payments at booking”, High, due 14/11/2026.

@Cade requirement

Client channelIn a message's thread

Starts a requirement from a message that's already in the channel. Cade privately offers a Start requirement button; the form is named from the message's first line, and once the requirement is posted the message is moved into its thread.

Example: reply @Cade requirement under “Could we get a monthly occupancy report as a PDF?”

/cade incident

Client channelTop level

Asks only what the incident is. Incidents are always Urgent and due Immediate, and are tracked straight away as a task in the incidents channel, with no tracking step. Needs an incidents channel set up for the channel pair.

Example: “Card payments failing at checkout for EU customers”.

@Cade incident

Client channelIn a message's thread

Reports an incident from a message already in the channel, as @Cade requirement does for requirements. The message is moved into the incident's thread.

@Cade track

Client channelDev channelIn a thread
  • In a requirement thread: a Track task button opens a form for the task title. The priority and due date come from the requirement, and the client keeps changing them there. The task is posted in the dev channel and linked both ways. A requirement has one task, so it can't be tracked twice. If an incident's task was deleted, this tracks it again.
  • In a message's thread in the dev channel: privately offers Track task, with the full form named from the message's first line. Once the task is posted, the message moves into its thread.

/cade track

Dev channelTop level

The team's own work: a form for the title, priority and an optional due date. The task has no client thread, so its changes aren't shared anywhere else, and the team owns its priority and due date.

Example: “Upgrade Node to 22 on staging”, Medium.
In a task thread

People, status, PRs and releases

These work in a task's thread in the dev channel or the incidents channel. The ⋯ menu on a task's card does the same for people, status, priority and due date without a command in the thread: pick one, save the form, and Cade notes who changed what in the thread.

@Cade assign developer @person

Dev channelIncidents channel

Adds people to a role: developer, reviewer or tester, several at once if you like. Cade mentions them with what to do next. Without anyone mentioned, @Cade assign shows a button per role (or just the one you name) that opens a form with that role's people, to add or remove.

  • Reviewers can be added before there's a PR. They're asked to review once one is linked.
Example: @Cade assign tester @Tom

@Cade unassign developer @person

Dev channelIncidents channel

Removes people from a role, and tells them they no longer need to do it. @Cade unassign @person removes them from every role. Without anyone mentioned it shows the same role buttons as @Cade assign.

@Cade status @Cade status in review

Dev channelIncidents channel

Without a status, shows a menu. With one, Cade sets it and reacts ✅. Statuses are to do, in progress, in review, in testing, client review and done, typed however you like (IN_PROGRESS, in-progress).

  • Done unpins the task and its requirement; moving it out of Done pins them again.
  • Done is told to the requirement thread.
  • Client review shows whoever set it a private Ask for approval button (set it again to get it back): pick who approves (whoever started the requirement, to begin with). Cade asks them in the requirement thread, or in the task thread when there's none, to Approve (the task goes to Done) or Not approve (back to In progress). Only they can click.
  • The client sees the team's own stages (To do, In review, In testing) as In progress.

@Cade pr add <link> @Cade pr remove <link>

Dev channelIncidents channel

Links or unlinks pull requests, one or several. GitHub, GitLab and Bitbucket links are recognised, and shown on the card as repo#number. Linking moves a task that's To do or In progress to In review and asks its reviewers; with no reviewer yet, Cade asks who should review, with a people picker.

Example: @Cade pr add https://github.com/acme/booking-web/pull/131

@Cade release @Cade deliver

Dev channelIncidents channel

Sends some of the task's PRs to the client before the whole task is done. A private Choose PRs button opens a form that lists the ones not sent yet and asks what they complete and who approves them (whoever started the requirement, to begin with). The approver gets them with Approve and Not approve, which only they can click, in the requirement thread, or in the task thread when there's none. PRs that weren't approved can be sent again. The task's status doesn't change.

  • The task thread hears the decision, mentioning the developers.
Example: send PR #128 as “Deposit checkout flow (20% default)”.
Priority & due date

Set by whoever owns them

In a requirement thread, the client sets these and the tracked task follows. In a task thread they work only for the team's own tasks. Incidents are always Urgent and due Immediate.

@Cade priority high

Requirement threadTeam's own task thread

One of urgent, high, medium or low. With a value Cade reacts ✅; without one it shows a menu. The card's colour strip follows the priority.

@Cade due 31/12/2026

Requirement threadTeam's own task thread

A date as DD/MM/YYYY (also with . or -, or as YYYY-MM-DD), or none to clear it. Without a value Cade shows a date picker.

Move & delete

Keep every channel tidy

@Cade move @Cade move <message link>

Client channelDev channelIncidents channelIn a message's thread

Moves a message into the right thread. Cade privately shows the open requirements and incidents (in the client channel) or open tasks (in the dev and incidents channels) to pick from. Messages only move within their own channel.

  • With a link: paste the link to a requirement's, incident's or task's message (Copy link on it, or on any reply in its thread) and Cade moves the message there straight away, with a ✅ on your command. Handy for bringing old threads in from before Cade, one after another: start with the oldest, so they land in order.
  • Slack can't move messages, so Cade copies it into the thread, quoted and credited to its author with a link back, replies under the original asking people to carry on there, and marks it with 📤 so it can be skipped.
  • Only the message is copied, not its replies or attachments, and a message is never moved twice.
  • If the original was pinned, it's unpinned: its new thread is where it's followed now.

@Cade detach /cade detach <link>

Task threadAnywhere, with a link

Unlinks a task from the requirement or incident it was tracked from, so the team owns it. Either form asks you first, privately, with Cancel and Detach, and Detach asks again. @Cade detach is sent from the task's thread, never the client's, and both threads are told. /cade detach with the task thread's link (Copy link on the task's message) does it quietly: nothing is posted in either thread, so no one is notified, and only you see the reply. Handy for detaching many at once.

  • The task stays where it is and still links to the thread it was tracked from, but no longer follows it: its priority and due date are changed from its own thread from then on, incidents' included.
  • The requirement's message stays, unpinned, saying where the work went. Cade stops tracking it, so it leaves the summaries and /cade brief.

@Cade delete @Cade remove /cade remove <link>

Requirement threadTask threadAnywhere, with a link

Asks first, with a prominent Cancel and a plain Delete that asks again. Only the person who asked can confirm. Cade deletes the root message and its own replies; people's replies stay under Slack's “This message was deleted”.

  • A requirement takes its task with it, and the question names the task.
  • A requirement's task is removed from the requirement thread instead, and Cade links to it. If the requirement has already gone, the task can be removed on its own.
  • The team's own task is removed from its own thread.
  • /cade remove <link> asks, and answers, only you, about whatever the link points at: a task or requirement, as above; a reply, which goes if Cade posted it; or any other message, whose thread loses Cade's replies, and the message too if Cade posted it. Slack only lets Cade remove its own messages.
Your work

Lists and standups, only for you

/cade tasks

Any channelOnly you see it

Your open tasks, grouped by what you do on each (developing, reviewing, testing), incidents first, then by priority and due date. In a channel pair's channel it shows that pair; elsewhere, every pair. Add any of:

  • development, review or testing: one role only
  • @person: their tasks instead of yours
  • -all: everyone's tasks, by status · -unassigned: tasks with no developer
  • -status=in-progress: one or more statuses, with commas (Done too, if named)
  • -due=@today, -due<@tomorrow, -due>=31/10/2026, -due=none: by due date
Example: /cade tasks review @Mia -status=in-review

/cade standup /cade standup -unassigned

Dev channelIncidents channelOnly you see it

Walks through the open tasks one developer at a time: you first, then everyone else, then the tasks with no developer. Each task has a status menu, and unassigned ones a developer picker; changes are posted in each task's thread. -unassigned goes through just the tasks with no developer. Built to share your screen in a standup.

/cade summary

Client channelDev channel

Puts the channel's work in its canvas (making one if the channel has none) and keeps it up to date as things change: an Open section by priority, then due date, incidents first, then a Closed section of the last 50 done, most recent first. In the client channel it lists requirements and incidents (title, priority, due date, status, whether tracked); in the dev channel, the pair's tasks, incidents' too (title, status, priority, due date, dev, reviewer, tester). With a Google Sheet linked to the group, the dev channel's canvas also links to it, for every task. Each title opens its thread. The table replaces what the canvas held.

/cade brief /cade brief <group>

Any channelOnly you see itNeeds the group's Google Doc

Writes an executive summary with you, one step at a time, and adds it to the group's Google Doc (its doc in cade.config.json), at the top of its Summary tab, as a section headed with the day it was written. Nothing is posted in Slack. Without a linked doc it says how to link one. It covers the channel's group, or the only one, or the one named. First pick the period, From and To dates: from the day after the last summary's period (the past week, the first time) to today, unless you change them. Then what was completed from the start of From to the end of To: untick any not to mention as done. Then, for a group with a client channel, each open requirement and incident, most urgent first, or, for a group without one, each open task in its dev and incidents channels: how it's going (on track, at risk, delayed or blocked), its progress such as 3/5, and any notes. Peek at threads shows the latest messages of its requirement thread and its dev or incidents thread, to help you write them. Health, progress and notes start as the last summary had them, to add to or change, and what the last summary said is shown above them, to compare. Last, the summary as it will read, with Add to the Google Doc. In the doc each title links to its thread, and notes are bullets under it. Back keeps your answers; nothing about the work itself changes.

/cade debrief /cade debrief <group>

Any channelOnly you see itNeeds the group's Google Doc

After going through the last executive summary with the client, reads its section of the doc back and compares it with what Cade wrote. A bullet of its own with no link is a new requirement, with the lines under it as its details; lines added under a requirement or task are points for its thread. They're suggested one at a time, to Apply or Discard. Apply on a point opens a text box with it, to edit, then posts it in the thread its title links to. Apply on a new requirement opens the requirement form, named from it, with an Initial message posted in its thread in the client channel once it's started; track it from there as usual. For a group without a client channel, it opens the task form instead, for a task in the dev channel, with the Initial message in the task's thread. Each is suggested once: /cade debrief again goes on with the rest, and finds anything added since.

@Cade help /cade help

Anywhere

Lists everything Cade can do. A bare @Cade or an unknown command does the same.

Just say it

Plain words Cade picks up

Cade notices these and offers, privately, to act on them. Nothing changes until you click.

Hand a task to someone

Task threadRequirement thread

Mention someone with what you'd like them to do:

  • Developer: “start working”, “work on”, “look into”, “pick this up”, “take this”, “take care of”, “handle this”, “fix this”, “assign this to”, “over to you”
  • Reviewer: “review” · Tester: “test”, “QA”, “verify”
  • In a requirement thread only developers are offered: Track and assign before it's tracked, Assign as developer after.
Example: “@Rex please start working on this, first cut by Friday?”

Paste a pull request

Task thread

Cade offers to link it. If your message also mentions people who aren't reviewers yet, it offers Link and add reviewer or Just link.

Example: “First pass is up: https://github.com/acme/booking-web/pull/128. @Mia can you review this?”

Post a new message

Client channelDev channelTop level
  • Client channel: Start requirement, Report incident, Move to existing or Not now.
  • Dev channel: Track as task, Move to existing or Not now.
  • Starting something from it names it from the message's first line and moves the message into the new thread.

Set it up

Up and running in minutes, with an AI agent guiding you.

Claude Code is the easiest, and any coding agent that can run terminal commands works too. It runs every command, checks it worked, and stops whenever it needs you. Your tokens never leave your terminal.

  1. 1

    Copy it to your repo

    Fork Cade on GitHub and clone your copy.

  2. 2

    Start the agent

    npm run setup with Claude Code, or paste the setup prompt into another agent.

  3. 3

    Follow along

    Click through the logins and Slack settings when it asks. That's it.
